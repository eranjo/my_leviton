Decode + HA state-sync notes (1.1.0b16)
================================================================================
Scope: post-SET readback + shared bus poll so HA tracks hardware. Floors
remain a separate product decision (Office ≈61%).

1) Root cause (confirmed)
-------------------------
LevitonLight was optimistic-only: after turn_on/turn_off/brightness it set
_is_on/_brightness locally and never read USB status. No async_update /
coordinator. Wall buttons and other controllers changed hardware without HA
noticing. iot_class=local_polling but nothing polled.

2) Status/live frame decoding (`_level_from_frame`)
--------------------------------------------------
- 0x04 status @ byte6 and 0x22 live @ byte10: adequate for 0x1E / 0x2E / relays.
- Truncated frames → level=?.
- Probe pitfall: early-return on first status=0 can capture OFF echo during
  OFF-then-SET. Sync readback collects for the full wait window and uses
  settle_reported_level() (last non-None sample).

3) Shipped in 1.1.0b16
----------------------
- utils/status.py: level_to_brightness, level_to_entity_state,
  settle_reported_level, read_light_level, poll_bus_levels (TTL cache +
  single-flight so N entities share one USB session).
- light.py: post-SET short readback; async_update via shared poll (~30s
  SCAN_INTERVAL). Relays get is_on from reported level too.
- Unit tests: tests/test_status_sync.py

4) Not shipped
--------------
- Continuous listen / wall-button instant push (would hold USB lock).
- Per-device OEM floor clamp / remapping.

5) Reload
---------
Restart Home Assistant (or reload the integration) after installing 1.1.0b16.
